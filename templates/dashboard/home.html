Overview

Django orchestrates policy, identity, quotas, and observability. Model weights and kernels stay in llama.cpp over HTTP. The dashboard uses Django sessions; programmatic access uses hashed API keys.

Runtime topology

  • edge NGINX terminates HTTP and forwards to Django (ASGI).
  • control plane Django validates requests and proxies OpenAI-compatible payloads.
  • data plane llama.cpp serves /v1/chat/completions on the internal network.

Health

Kubernetes-style probes map cleanly to load balancers and compose healthchecks.

  • /health/live — process up (cheap).
  • /health/ready — database reachable.
  • /metrics — Prometheus scrape (treat as sensitive in production).

Configuration

Django never loads GGUF weights. It only needs the upstream base URL.

LLAMA_CPP_BASE_URL={{ llama_cpp_base_url|default:"(unset)" }}
